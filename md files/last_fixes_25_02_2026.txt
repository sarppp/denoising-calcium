  ---

  All three ablation configs have model.name: n2v3d. The only difference between

  ---
  Is that loss transferable to Mamba?

  Yes, with very high confidence — and here's why:

  Look at train.py:133:

  def step_mamba3d(model: nn.Module, batch: dict[str, Any], cfg) -> Tensor:
      return step_n2v3d(model, batch, cfg)

  step_mamba3d literally is step_n2v3d. Same blind-spot masking via
  stratified_blindspot(), same Anscombe transform, same _simple_loss()
  dispatcher, same everything — only the nn.Module that processes the masked
  volume is different. The loss is computed identically.

  So when you pick NLL (or MAE) from the ablation, you're picking:
  - which loss function is numerically stable on A1/B1 data
  - which loss surface the optimizer converges better on given Poisson-Gaussian
  noise

  Neither of those properties is specific to the UNet3D backbone. The Mamba
  bottleneck changes the feature extractor, not the loss landscape or the noise 
  statistics. Whatever makes NLL unstable on A1/B1 (R²≈0.27 noise model
  mismatch) will affect Mamba exactly the same way.

  ---
  Mamba uses 3D + blind-spot

  Confirmed: step_mamba3d → step_n2v3d → stratified_blindspot(vol, ...). Same 3D
   voxel masking, same self-supervised objective, same gain augmentation path.
  The only architectural difference is MambaUNet3D replaces the UNet skip
  connections with a Mamba state-space bottleneck — but the training protocol is
   identical.

  ---
  Practical workflow: Run the 3-arm ablation → pick a loss → use that same
  loss.name: in configs/mamba3d.yaml → done.

  What this means for your ablation

  The ablation is now more critical, not less. The evidence points toward:

  1. NLL is theoretically correct only for C2/D2 — the only stacks with good R².
   On A1/B1 the noise model is badly misspecified, so the NLL gradients are
  computed against the wrong variance function
  2. A1/B1 NLL gradients may be noisy or biased — you're fitting a
  Poisson-Gaussian model to what is actually a mixed/unknown noise process
  3. MAE has no distributional assumptions — it doesn't care what the true noise
   model is; it just minimizes absolute error, which is robust to model
  misspecification

  Concretely, the risk scenario the ablation is designed to catch:
  - NLL trains fine on C2/D2 patches but produces NaN or large loss spikes on
  A1/B1 patches

  lose that on A1/B1. Run the ablation to confirm — the 10-epoch result will
  tell you definitively.

  ---
  2. What does samples_per_epoch mean?

  Your stacks are huge (~1500 frames × 490×490 pixels each). You can draw
  millions of random patches from them. samples_per_epoch just controls how many
   random patches you draw before calling it one epoch — it doesn't limit what
  data you can see, it just sets the clock.

  - 2000 → draw 2000 random patches → form batches → do 250 gradient steps →
  call it epoch 0
  - 10000 → draw 10000 patches → 1250 gradient steps → call it epoch 0

  More samples per epoch = more learning per epoch, but also slower epochs. For
  the ablation 2000 is fine — you just want to compare losses, not maximise
  score. For full training, 2000 × 100 epochs = 200k total patches seen, which
  is reasonable.
